# Reliability Witness

Reliability Witness is being built for source-bound laboratory observation of stochastic-computing and spiking designs: committed device exposure, observed event classes, voter interventions, recorded conditions and explicitly qualified rate bounds. This checkout contains repository validation tooling and documentation. Full foundation qualification is in progress. There is no installed reliability-analysis package, soak runner, public reliability-analysis command or qualified reliability report.

## Boundary

Reliability Witness owns laboratory observation orchestration, durable joint event and coverage records, independent accounting, statistical analysis and reports. SC-NeuroCore owns measured designs and mitigation. Loop Timing Witness and target adapters supply admitted instrumentation and timebase. Evidence Manifest Toolkit supplies shared evidence operations. Flight Recorder owns field attestation; Studio renders existing results.

Conditions are recorded, not controlled. No thermal chamber, radiation beam, hardware run, safety certification or population silent-error guarantee is claimed. Model-level resilience simulation is complementary to physical observation.

## Current tooling

Seven repository controls inspect metadata, source attribution, workflows, dependency alignment, native documentation, inventory and preflight orchestration. Native-tool bootstrap checks selected executable and licence bytes. Domain capabilities, claims and qualified formats remain empty at architecture-only maturity.

Use the exact environment in [Contributing](CONTRIBUTING.md). Named commands are make metadata, make source-provenance, make workflows, make dependencies, make docs, make inventory and make licence. Full CI/preflight belongs in CI or an explicitly admitted pre-push environment. See [Validation](VALIDATION.md).

## Intended evidence

A report will retain prior complete workload, devices, observer and clock, committed exposure, gaps, event classification, stopping and inference assumptions, numerical uncertainty, conditions and any declared budget. Zero observed events can support a qualified upper bound under admitted assumptions; they never establish a zero underlying rate.

Read [Architecture](ARCHITECTURE.md), [support](SUPPORT.md), [security reporting](SECURITY.md) and [citation metadata](CITATION.cff). No released domain package, actual soak, numerical guarantee, physical result, DOI or hosted status is claimed.
